# Tasogare 黄昏 自选延迟 GPU 版

当前版本：`v2.2.6`

## v2.2.6 更新：自动查询节点 ASN 与 IPv4/IPv6 国家

新版主题可以读取 **Komari 服务端插件**自动生成的节点网络信息，不再需要逐台填写 ASN 或国家。主题 ZIP 本身不会读取到服务端私有 IP：官方公开节点 API 默认隐藏 IP。

**要自动显示，需同时安装两个包：**

1. 主题：`komari-theme-tasogare-gpu-2.2.6-komari.zip`，在 Komari「主题管理」安装。
2. 可选服务端插件：`komari-node-network-meta-plugin-2.2.6.zip`，在 Komari「插件管理」安装、启用并批准 `allowRoutes` 和 `allowSystemRPC` 权限。需要支持 JavaScript 插件的 Komari 服务端版本。

插件使用已在 Komari 服务端保存的完整节点 IPv4/IPv6，仅在服务端查询 `https://api.ipapi.is/?q=<IP>` 的 ASN 和国家。结果按节点 UUID 缓存并以精简 JSON 提供给主题：

```json
{
  "nodes": {
    "<uuid>": {
      "asn": "AS3258 xTom Japan Corporation",
      "ipv4_country": "Japan",
      "ipv6_country": "Japan"
    }
  }
}
```

**公开数据绝不包含原始节点 IP；隐藏节点不返回；私有 Komari 站点不向访客返回此数据。** 插件会把公网 IP 提交给第三方查询服务，安装前请确认你接受这一点。免费服务有查询限额及准确性限制，断网或查询失败时保留“待配置”；无公网 IPv4/IPv6 的节点对应字段也无法自动识别。IP 查询结果缓存约 12 小时。

插件开启后，可访问同源 `/api/vlongx/node-network-meta` 验证返回的 ASN、IPv4/IPv6 国家。接口无需输入 IP，不接受用户指定目标地址。

原有节点标签可选，配置后覆盖自动查询值：

```text
asn:AS3258 xTom Japan Corporation;ipv4:Japan;ipv6:Japan
```

所有节点的系统、ASN 和 IPv4/IPv6 三行仍固定显示；未能自动识别时显示“待配置”。保留 v2.2.5 的硬件信息、GPU、延迟与丢包、月流量周期等功能。

### 配置示例

在 Komari 后台给相应节点添加标签（以半角分号分隔）：

```text
asn:AS3258 xTom Japan Corporation;ipv4:Japan;ipv6:Japan
```

> Komari 公共节点 API 不暴露节点原始 IPv4/IPv6 地址；ASN 和 IP 归属标签需由管理员填写真实资料。未填写时固定显示“待配置”。

## 延迟展示逻辑

首页卡片与点击弹窗采用两套范围：

- **首页卡片**：用户从 Komari 已创建的延迟任务中自由选择 `0～3` 项；
- **点击延迟区域**：打开独立弹窗，展示当前节点被分配的全部延迟监测任务，不受首页 0～3 项选择限制。

TCP、ICMP、HTTP 可以任意混合。每个首页展示项严格对应一个任务，不会把不同城市或不同任务自动平均。

## 卡片名称

首页自动压缩运营商名称并显示协议徽标：

```text
广东联通 TCP  → 广东·CU  [TCP]
广东电信 ICMP → 广东·CT  [ICMP]
广东移动 TCP  → 广东·CM  [TCP]
东京 TCP      → 东京     [TCP]
```

也可以在选择器中填写自定义名称。丢包列不再重复显示任务名称，只保留数值和状态条，使左右两列更整洁。

## 点击延迟详情

点击卡片延迟区域后：

- 加载该节点全部可用延迟任务；
- 显示历史延迟折线与对应丢包/断连状态；
- 支持单独隐藏线路、全选和全不选；
- 只显示延迟与丢包事件，不显示 CPU、内存、流量等硬件详情；
- 点击关闭按钮、遮罩或按 Esc 关闭。

## GPU / iGPU 详情

点击服务器卡片打开节点详情后：

- CPU 型号完整显示；
- 检测到真实 GPU 时才显示 GPU、GPU 使用率和 GPU 显存；
- Intel/AMD 集成显卡没有独立显存时显示“共享内存”；
- 无 GPU 的服务器不会显示空白 GPU 项目；
- Sensor Hub、Management Engine 等非显卡设备会被过滤。

## 每月流量周期

主题设置中的 `trafficResetDay` 可填写 `1～28`，表示每月流量周期的重置日。

例如填写 `13`，卡片会按每月 13 日开始的新周期计算当前周期已用流量，而不是直接显示 Agent 的长期累计流量。

如果不同服务器重置日不同，可以给节点添加标签：

```text
traffic-reset:13
```

该标签会覆盖该节点的全局 `trafficResetDay` 设置。
